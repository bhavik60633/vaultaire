## 6. Account and machine security

These are the owner's tasks; nobody else can do them.

- [ ] Passkeys on the GitHub account, the Google account used for Play Console, and the email account behind both; paper backup codes stored offline
- [ ] **Disk encryption on the development machine.** This machine runs Windows 11 **Home**, which does not include BitLocker. Check *Settings → Privacy & security → Device encryption*. If it is not offered, record the risk and keep signing keys off this disk until a solution exists.
- [x] **Windows Firewall on for every profile** (Domain, Private and Public). Found 2026-09-29: the Public profile was off while the home Wi-Fi was marked Public, so the machine accepted inbound connections from any network it joined. Fixed and verified the same day: firewall on for all profiles, home Wi-Fi marked Private, and Python allowed through on Private only (its Public rules disabled).
- [ ] A separate Windows user account for development
- [ ] No signing keys, keystores or test vaults in any synced folder (OneDrive included)

## 7. Independent review

Under Amendment 1 (zero budget), the paid consult is replaced by free options. The requirement for review by someone other than the developer does not go away.

- [ ] Specs published in the public repository with a call for review
- [ ] At least one application made to a free audit or funding programme (for example NLnet NGI Zero, OSTIF, Open Technology Fund Red Team Lab; eligibility and open calls vary)
- [ ] At least one reviewer other than the developer has read `crypto-spec.md` and `vault-format.md`; their findings are recorded here, with how each was resolved
- [ ] Until an independent audit is complete, every build and listing says: **"Unaudited beta. Do not store real credentials."**
