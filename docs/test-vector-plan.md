# Test-vector plan

| | |
|---|---|
| Status | **Proposed** for G0 (2026-09-30) |
| Implements | [crypto spec §12](crypto-spec.md#12-test-vectors) |
| Vectors | `tests/vectors/v1/` (JSON; synthetic data only) |

## 1. Purpose

Every construction in the crypto spec and the vault format is computed by **two independent implementations**, which must agree byte for byte:

1. **The reference:** a small, dev-only Python implementation in `tools/vectorref/`, written **from the spec text alone**.
2. **The product:** the Rust core (`core/vault-core`).

A composition bug, such as a wrong label, the wrong salt, bytes concatenated in the wrong order or a missing length prefix, can pass unit tests, survive code review and still produce a working but non-conforming vault. Two implementations written separately, from the same spec, rarely make the same mistake.

## 2. Order of work (change from §12.2)

§12.2 says the vectors are generated by Rust and cross-checked by Python. This plan **reverses the order**: the Python reference is written first, during G0, before any product code.

- Writing it forces every ambiguity in the spec into the open **while the spec is still cheap to change**. Any question the Python author has to guess at becomes a spec fix.
- The Rust core then has a complete, fixed target from its first line.
- Python is test tooling, not product code, so this fits the G0 rule.

The G1 criterion is unchanged: Rust must reproduce every vector exactly.

## 3. Independence rules

- The Python reference is written from `crypto-spec.md` and `vault-format.md` only. Its author does not read the Rust code first, and it is never translated from Rust.
- It uses **different libraries** from the core:

| Primitive | Rust core | Python reference |
|---|---|---|
| XChaCha20-Poly1305 | RustCrypto `chacha20poly1305` | libsodium via PyNaCl (`crypto_aead_xchacha20poly1305_ietf`) |
| Argon2id | RustCrypto `argon2` | `argon2-cffi` (bindings to the reference C implementation) |
| HKDF-SHA256, HMAC-SHA256, SHA-256 | RustCrypto `hkdf`, `hmac`, `sha2` | `cryptography` (OpenSSL) and `hashlib` |
| Deterministic CBOR | `minicbor` with hand-written encoders | Hand-written encoder for the vault's CBOR subset (no library) |
| NFC | `unicode-normalization` | `unicodedata` (standard library) |

- Python dependencies are pinned with hashes (`pip install --require-hashes`).

## 4. Determinism: where randomness goes

Every random value (keys, salts, nonces, ids) is an explicit **input** in the vectors. The core exposes its constructions with injectable randomness **only** behind a test-only Cargo feature (`test-vectors`). A CI check fails if that feature is enabled in any release build.

## 5. Vector format

One JSON file per construction, all binary values as lowercase hex:

```json
{
  "construction": "slot/pwd",
  "spec": "crypto-spec §4.3",
  "format_version": 1,
  "vectors": [
    {
      "id": "pwd-001-ascii",
      "comment": "ASCII password, provisional parameters",
      "inputs": { "password_utf8": "…", "salt_pwd": "…", "vault_id": "…", "argon2": { "m": 65536, "t": 3, "p": 1 },
                  "hw_hmac_key": "…", "vk": "…", "nonce": "…", "slot_id": "…" },
      "intermediates": { "h_pwd": "…", "hw_in": "…", "hw_pwd": "…", "kek_pwd": "…", "ad_slot": "…" },
      "output": { "wrapped_vk": "…" },
      "expect": "ok"
    }
  ]
}
```

- **Intermediates** make a mismatch point at the exact step that differs.
- `expect` is `"ok"` or `"error:<code>"`, where `<code>` is the core's error name, so negative vectors check *which* failure happens, not just that one does.
- Hardware keys are replaced by fixed software stand-ins (a fixed SK for KS-BIO, a fixed HMAC key for K_pwd), as §12.2 says.

### 5.1 Error names

The negative vectors name the core's internal error, so they check *which* step failed. The names below are proposed for the spec (crypto spec §9.4 and §11). One rule governs them: **an error may only distinguish failures that do not depend on a secret.**

| Error | Import step (§9.4) | Depends on a secret? |
|---|---|---|
| `too_large` | 1, 3 | No |
| `not_a_backup`, `unsupported_version` | 2 | No |
| `malformed_header` | 3 | No |
| `params_out_of_range`, `insufficient_memory` | 4 (and Q8) | No |
| `wrong_recovery_key` | 5 | Only on RS, which the user just typed. It is shown before any work, on purpose (§9.2) |
| `auth_failed` | 6 and 7 | **Yes.** Wrong password, wrong Recovery Key, damaged or tampered data all collapse into this one error and one message, as §9.4 requires |
| `truncated` | Length checks before 6 | No |
| `non_canonical`, `schema_violation` | 7, 8 (after authentication) | No: the data is already authenticated |

For unlock, the same rule applies: every failure that depends on the password or the hardware factor is one error, `unlock_failed` (§11).

## 7. Backup tamper matrix

Each case starts from the valid backup in `backup.json` and must fail with the stated error, **before** any Argon2id work where marked ✱:

| Change | Expected failure |
|---|---|
| Wrong magic ✱ | `error:not_a_backup` |
| Unknown version ✱ | `error:unsupported_version` |
| Header over 4 KiB or file over 64 MiB ✱ | `error:too_large` |
| Argon2id parameters out of range ✱ | `error:params_out_of_range` |
| Parameters above the device memory cap (Q8) ✱ | `error:insufficient_memory` |
| Wrong `rs_id` ✱ | `error:wrong_recovery_key` |
| One bit flipped in each header field, then valid length | `error:auth_failed` |
| One bit flipped in `wrapped_FK` or `payload_ct` | `error:auth_failed` |
| Truncated at every region boundary | `error:truncated` or `error:auth_failed` |
| `wrapped_FK` and payload from two different backups swapped | `error:auth_failed` |
| Valid file but non-canonical CBOR inside the payload | `error:non_canonical` |

## 8. Guarding the vectors themselves

- **Label mutation test:** for each label, changing one byte must change every output that depends on it. This proves that every label is actually used, and in the right place.
- **Two-way check in CI:** the Rust suite verifies every vector, and `core/vector-gen` regenerates the files; `git diff --exit-code tests/vectors/` must be empty.
- **Slow cases:** full-cost Argon2id runs in about 0.1–0.4 s per derivation, so the whole suite stays within a few minutes. No reduced-cost shortcuts: the spec rejects parameters below the floor, so vectors use the real ones.
- **Versioning:** vectors belong to `format_version = 1`. A format change adds `v2/`; `v1/` is never edited.

## 9. Exit criteria

- **G0:** this plan agreed by the reviewer.
- **Before G1 starts:** the Python reference produces every positive vector and the tamper matrix, and every spec ambiguity found along the way is fixed in the spec.
- **G1:** the Rust core reproduces every vector exactly, and every negative vector fails with its stated error.
